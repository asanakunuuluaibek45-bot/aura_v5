# Миграции для филиалов и перемещений

Инструкция относится к функциональности из ветки feat/multi-branch-transfers-20261124.

## Существующая база данных

Применяй только миграции, которых ещё нет в этой базе, строго по порядку и по одной:

1. supabase/migrations/021_branch_access_and_transfers.sql — бизнесы, филиалы, права доступа и базовые перемещения.
2. supabase/migrations/022_branch_aware_products_and_sales.sql — местоположение товаров и проверки продаж по филиалам.
3. supabase/migrations/023_branch_transfer_partial_receipt_and_cancel.sql — частичная приёмка, отмена возвращённых товаров и аудит.
4. supabase/migrations/024_branch_transfer_scan_access.sql — ограниченный поиск по QR в остатках филиала или выбранном перемещении.

Если 021–023 уже применены, для этого обновления нужна только 024. Если применены лишь некоторые, продолжай с первой ещё не применённой миграции. Не запускай миграцию повторно; сначала проверь журнал или обычную процедуру миграций проекта, а при сомнении остановись и уточни состояние базы.

Перед обновлением production сделай резервную копию и сначала проверь порядок на staging. Не запускай следующий файл, если предыдущий завершился ошибкой.

## Новая база данных

supabase/schema.sql — консолидированная схема для первоначальной настройки новой базы; в конце она включает 021–024 через psql-команды \ir. Применяй её один раз через psql из каталога supabase. Не применяй консолидированную схему поверх существующей базы и не запускай после неё те же четыре файла отдельно.

Эти инструкции не выполняют миграции автоматически.
