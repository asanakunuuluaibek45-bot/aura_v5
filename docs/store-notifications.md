# Уведомления магазина

Только подтверждённый суперадминистратор может отправлять и удалять уведомления.
Получатель — все подтверждённые администраторы/продавцы одного магазина или один
из них. Ответов и чата нет. Каждый получатель отмечает уведомление прочитанным
для себя; сообщение другого магазина или другого пользователя недоступно.

## Обновление Supabase

1. Сначала примените **только** `supabase/migrations/014_store_notifications.sql`
   в Supabase SQL Editor. Миграция выполняется одной транзакцией. Не запускайте
   повторно `012_platform_announcements.sql` и не удаляйте существующие таблицы.
2. Проверьте наличие новых таблиц:

   ```sql
   select to_regclass('public.store_notifications') as notifications,
          to_regclass('public.store_notification_reads') as read_receipts;
   ```

3. После применения миграции разверните ветку с этим кодом. При отсутствии
   миграции интерфейс показывает ошибку, а не ложное пустое состояние.
4. В `/admin/notifications` отправьте тестовое сообщение одному сотруднику
   тестового магазина. Проверьте под двумя разными сотрудниками этого магазина
   и сотрудником другого магазина: личное сообщение видит только адресат.
   У магазинной рассылки прочтение одного сотрудника не меняет прочтение другого.
5. После удаления суперадминистратором уведомление исчезает при обновлении
   списка (автоматическое обновление каждые 20 секунд в открытом приложении).

Это уведомления внутри приложения, не браузерные push-уведомления.

## Совместимость

- `/notifications` и `/crm/notifications` открывают центр уведомлений.
- Старые `/announcements` и `/crm/announcements` открывают тот же центр.
- Существующие `platform_announcements`, их функции и история не изменяются.
  Старые общие объявления доступны как «Общие уведомления», прежняя форма
  управления ими остаётся в `/admin/announcements`.
- Заявки на регистрацию суперадминистратора сохраняются отдельно от сообщений.
- Мобильный клиент использует тот же явный allowlist действий и серверные
  проверки. Данные уведомлений не добавляются в офлайн-очередь.

## Проверки

```sh
node --experimental-strip-types --test tests/store-notifications.test.mjs
npm run typecheck
npm run build
```

Наличие таблиц само по себе не подтверждает доставку или правильность RLS.
Проверки с реальными пользователями нужно выполнять в тестовом магазине после
применения миграции. Ключ service role не нужен и не должен попадать в браузер.
